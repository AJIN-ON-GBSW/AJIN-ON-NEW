### Performance 계산과 키

- 법인: `ajin`, `ajincar`, `ajajin`, `ajinelec`.
- 항목: `incoming`(10), `claim`(35), `audit`(30), `outsourcing`(15), `qm`(10).
- 월별 저장 키: `법인|항목|행|월인덱스`. 월 인덱스 0~11은 2025-09~2026-08.
- 입고불량 행: `receipts`, `domestic`, `kd`. PPM은 `(domestic + kd) / receipts * 1,000,000`; 입고 0이면 미계산. 반기 PPM은 월 평균이 아니라 합계 비율.
- 클레임 행: `receipts`, `claimTotal`, `w1`, `w2`, `w3`. 변제율은 클레임 합계/입고금액×100.
- 기준값/직접점수 키: `법인|항목`.
- 원본은 수치 0을 `value || ''`로 표현하는 결함이 있어 0이 빈 칸처럼 표시될 수 있다. 실제 서비스는 `??`를 사용해 0을 보존해야 한다.
- 원본 입고불량 점수는 “산식 확인 대기”, 클레임 점수는 `[점수]`, 적용 입고금액은 `[금액]`이다. 정확한 구간/기준값을 알 수 없는데 점수 산식을 창작하면 안 된다. 원본이 제공한 확정 계산과 직접입력까지만 연결한다.

### Internal 일정과 공개 동작

- 1차 10개 공장, 2차 13개 공장. 기본 연도 2026.
- 날짜를 바꾸면 해당 차수 목록을 날짜순 정렬하고 날짜 없는 공장을 끝으로 보낸다. 카드 이동은 두 공장 자리 교환이 아니라 선택 공장을 대상 위치 앞에 삽입하는 동작이다.
- 조회자 모드의 미래/미정 불시평가: 날짜·순서 비공개, 비공개 공장들은 가나다순. 완료 공장 일정은 표시.
- 원본 “평가 완료”는 완료 기록 없이 단순히 평가일이 오늘보다 과거인 것으로 계산된다. 이것을 실제 결과 등록 완료 상태로 오해하면 안 된다.

### EvalHistory 데이터·필터·내보내기

- 원본 `EVENTS`는 2022~2026 내부 현장평가의 회차/공장/항목별 건수·판정 코드 집계이다. `ITEMS`는 28개 평가항목, 판정은 보완/일부미흡/다수미흡/양호/미기재.
- 원본 제공 데이터 종류는 `internal`뿐이다. `all`은 이 데이터의 합계이고 qstar/sq/iatf는 “준비 중”. 현재 HTML 일부 유형 탭은 정적인 링크이므로 로직의 모든 반환값이 화면에 실제 노출되지는 않는다.
- 상세 모달은 항목·공장·일자·관리번호를 보여주며 부적합 설명/개선대책 실제 본문은 원본에 없다. 집계 숫자로 없는 본문을 만들어내면 안 된다.
- 내보내기 옵션: 현재 필터/전체, 한 시트/공장별/연도별, 요약 시트, 공장×평가항목 표. 열: 평가 종류, 연도, 점검일, 차수, 공장, 관리번호, 평가항목, 판정, 부적합 사항, 개선대책, 조치 상태.
- 원본 `doExport()`는 `exportDone: true`만 설정한다. 실제 XLSX 생성·다운로드는 없다. 서비스는 실제 파일을 생성해야 한다.
- 원본 `filterLabel`/엑셀 예상 행수는 연도·공장 위주로 계산해 영역·판정 필터와 차이가 날 수 있다. 실제 파일은 사용자가 선택한 조건과 일치해야 한다.

### IATF 계산과 날짜

- 사업장 9개와 법인 8개. 본사·경산은 같은 인증서로 묶여 있다. 구어·입실·준텍은 인증 없음.
- 심사 종류: 최초, 갱신, 사후1차, 사후2차. 다음 차수: 최초/갱신→사후1차→사후2차→갱신.
- 날짜는 정확한 `YYYY-MM-DD` 또는 연도만 `YYYY`. 미정/기록 없음/추정 기한을 구별한다.
- 원본의 갱신 기한은 최근 최초·갱신 시작일+3년−1일, 사후는 직전 심사+1년. 미래 일정 없으면 “일정 미등록” 추정 표시.
- 화면은 현재 날짜로 D-day를 계산하므로 고정 캡처와 실행일에 따라 값이 달라진다. 원본의 인증서 번호·보고서 수치 등 `[placeholder]`를 실제 사실로 바꿔 제시하면 안 된다.

## DC 템플릿을 React로 옮길 때

- 원본 루트 `<x-dc>`, `<helmet>`의 font/style, `<script type="text/x-dc">` 안의 `Component extends DCLogic`를 분리한다. 외부 `@@RT@@`와 iframe `parent.postMessage` 라우터 스크립트는 React 서비스에서 실행할 필요가 없다.
- `<sc-for list="{{list}}" as="row">`는 중첩 가능하며 부모 scope를 상속한다. 형제 반복 변수 이름이 같은 경우가 있으므로 각 반복 scope를 분리한다. 표시용 `hint-placeholder-count`는 실제 행수가 아니다.
- `<sc-if value="{{condition}}">`는 JS truthiness를 따른다. `hint-placeholder-val`은 실제 조건의 대체값이 아니다.
- 화면 템플릿의 492개 보간식은 모두 단순한 객체 경로 또는 true/false이다. eval이 필요 없다. 일부 `renderVals()` 반환값이 템플릿에서 사용되지 않으므로 반환값만 보고 미제공 화면을 만들지 않는다.
- 전체 값 보간은 타입을 보존해야 한다: onClick/onChange 함수, disabled boolean, input value 0, SVG 속성, aria 속성. 문자열 치환만으로 처리하면 기능이 깨진다.
- `style="... {{r.lossColor}} ..."`, `cursor: {{c.cursor}}` 등 문자열 중간 보간도 존재한다. inline CSS 문자열은 React의 camelCase 스타일 객체로 변환해야 한다. SVG는 strokeWidth, strokeLinecap, strokeLinejoin 등의 React 속성명으로 바꾼다.
- `<sc-for>`가 table/thead/tbody/tr 내부에 존재한다. 일반 브라우저 HTML 파서의 foster parenting이 custom 태그를 테이블 밖으로 옮길 수 있으므로 원본 구조를 보존하는 파싱/변환을 써야 한다.
- `for`→`htmlFor`, class→className, 선택 폼 onChange/value, disabled boolean, 키를 처리한다. input/textarea가 편집 불가인 controlled 값이 되지 않도록 주의한다.
- `*.dc.html#fragment`는 React 라우트와 fragment로 변환한다. 링크 `href="#"`를 빈 새 페이지로 이동시키지 않는다.
- 원본의 max-width, 폰트, 색상, 간격, 카드/테이블 구조를 보존하면서 긴 테이블에는 가로 스크롤을 제공한다. 전체 HTML을 iframe으로 감싸는 것은 React 구현이 아니다.
